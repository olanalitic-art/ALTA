Сводка утверждённых параметров и требований, 16.11.2026. Спорные значения и неподтверждённые предположения сюда не входят.

## 2. Ресайз сайдбаров

Подробно: [`sidebar-resize.md`](sidebar-resize.md).

- Ширину левой и правой панелей меняют перетаскиванием вертикального разделителя.
- Каждый сайдбар 248–420 px.
- Центральная область не уже 512 px. Если расширение сайдбара нарушит это, расширение останавливается.
- Центральная область занимает оставшееся место.
- Фактический максимум сайдбара может быть меньше 420 px из-за ограничения центра.

Две открытые панели: `W_center = W_viewport − W_left − W_right − 20`.
`W_left,max = min(420, W_viewport − W_right − 512 − 20)`. Для правой панели симметрично.

Контрольный пример: ширина 1380 px, две панели по 420 px — центр 520 px.

## 3. Состояния и взаимодействия

- Визуальные состояния: hover, focus, selected, pressed, loading, disabled.
- Переключение вкладки меняет активную вкладку и соответствующее содержимое интерфейса.
- Компиляция — последовательность состояний: initial → compile-pressed → compiling → compilation-error.
- При компиляции меняются состояние кнопки, прогресс, консоль и диагностика по текущему этапу.
- После компиляции показываются сообщения диагностики. Состояние Status Bar согласуется с состоянием сценария.
- Строки таблицы, размеры панелей, фокус, прокрутка и активная вкладка меняются как состояние существующего интерфейса, а не как отдельные страницы.

## 4. Структура и реализация

- Постоянная оболочка интерфейса (Shell) содержит основные области и не дублируется для каждого состояния. В репозитории это [`03_master`](../03_master/README.md).
- Интерфейс делится на логические компоненты: TopBar, Toolbar, Sidebar, ContentTab, CodeEditor, VariablesTable, StatusBar, SplitPane.
- Сохранять существующий стек проекта и переиспользовать существующие компоненты.
- Использовать дизайн-токены, не размножать HEX-значения внутри компонентов.
- Не заменять иконки интерфейса emoji или текстовыми символами.
- Проверять клавиатурный фокус, клики, выделение элементов и оба разделителя.
- Не допускать горизонтального переполнения интерфейса.
- При переносе из Figma проверять геометрию, отступы, границы, типографику, цвета и активные состояния.

## 5. Маркер компонентов библиотеки

- Маркер 1 × 1 px цвета `#FE01FC` в правом верхнем углу каждого компонента, включая вложенные.
- Маркер не меняет геометрию и поведение компонентов.

Реализация: [`01_foundations/runtime/component-marker.css`](../01_foundations/runtime/component-marker.css).
